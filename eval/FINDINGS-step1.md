## 실험 로그

### P1 (프롬프트 제약): isOpinion 13% → 75% (+62pt)
- 투표 스키마 프롬프트에 "정답 없는 질문만 + wordcloud 기준 + 좋은/나쁜 예시" 추가
- wordcloud 활용 0% → 25%. 잔존 실패: 지식 문제를 형식만 wordcloud로 바꾸는 회피

### P1b (검증 루프, 원문 미제공): isOpinion 75% → 75% (개선 없음, 3회 반복 n=24)
- 생성 후 "정답 존재?" 자체점검 + 탈락 사유 피드백 재생성 (≤3회)
- **기각된 부분**: 검증기가 질문만 보고 판단 → "원문이 이미 결론을 낸 확인형 질문"을 3/3회 통과시킴
- 교훈: 검증 루프의 효과는 검증기의 "입력"에 좌우된다 — 루프 구조 자체는 무죄

### P1c+P2+P3 = v1 (병합 실험, 3회 반복, n=107)
- P1c: 검증기에 원문 컨텍스트 제공 / P2: 역할극 키워드 명사구 제약+사실검증 / P3: 퀴즈 출제규칙 4개

  "방향 뒤집기 오답"이 정답과 아슬아슬한 보기를 만들어 유일성(78~80%)까지 흔드는 것으로 추정.
- MiniMax 단독 구성의 파레토 프론티어가 그려짐: (회상 위주, 98% 정확) ↔ (적용 40%+, 87% 정확, 오답 우수)

## 최종 채택 구성 (v2, 프로덕션 배포)
- 투표: P1 프롬프트 제약 + P1c 원문 포함 검증 루프 → isOpinion 13%→88%
- 역할극: P2 명사구 키워드 제약 + 원문 대조 사실 검증 루프 + P5 공백무시 매칭 → 키워드 도달성 100%, 사실 정확성 63%→82%
